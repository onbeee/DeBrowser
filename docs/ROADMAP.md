## 已完成阶段摘要

- **Stage 1–3**：Wails v3 + Go + React 应用外壳、便携数据布局、单实例保护与生命周期治理；SQLite 版本化迁移、仓储层与迁移前备份；实例元数据管理与 Profile 删除安全模型。
- **Stage 4A**：凭据 Vault（DPAPI 保护、SQLite 只存不透明引用）与代理数据结构。代理功能本身已移除，Vault 与历史数据作为兼容层保留。
- **Stage 5A**：直接启动——无首次启动欢迎页或选择页，不扫描、不检测、不自动迁移任何外部旧数据；便携布局稳定。
- **Stage 5B 与统一自动记录系统**：运行 / 操作 / 错误三类 JSONL 记录；统一事件模型以 operation_id 贯穿一次用户操作的全部记录；总容量用户可配（默认 100 MB），超出按最旧优先自动清理；数据管理页按类别与日期范围导出。这是唯一的记录系统，没有独立的操作审计或诊断导出模块。
- **Stage 9A**：浏览器手动登记（纯路径）——只保存用户所选程序的路径与显示名，不做任何检查；实例按登记 ID 关联，路径由服务实时解析；被实例引用的登记禁止移除。
- **Stage 9B**：实例真实运行——每实例独立实例文件与真实浏览器进程，进程身份严格核验（PID + 创建时间 + 可执行路径 + 命令行），退出自动感知，DeBrowser 重启后重新识别仍在运行的实例，无法确认时进入安全保持状态；关闭只走优雅关闭。
- **PR #14**：实例页面功能与交互完善——名称自然排序、批量选择与批量启动/关闭/删除、批量创建、实例文件横向按钮与独立选择弹窗、工具栏固定。

## 当前阶段与下一步：Stage 9C（书签管理已实施，CDP 尚未开始）

- 书签管理（已实施，等待负责人审查）：DeBrowser 书签资源库（文件夹树、拖拽排序、新建/编辑/删除）与实例真实书签管理并行存在、互不自动覆盖；实例书签通过直接读写其 Profile 的 Chromium 原生 `Bookmarks` 文件实现，仅限已确认停止的实例（运行中与无法确认状态跳过并反馈），支持分发同步与跨实例聚合搜索、批量编辑、批量删除。机制与安全规则见 [ARCHITECTURE.md](ARCHITECTURE.md) 的「书签机制」。
- CDP 接入（尚未开始）：为每个运行中实例接入一个仅绑定 localhost 的 CDP 端口。
- 边界：范围限于此。不扩展浏览器自动化框架、远程控制平台或其他复杂能力；CDP 端口永不暴露到 localhost 之外。

## 后续计划

### 代理配置（Stage 6C）——待开发

代理配置仍属于 DeBrowser 的后续产品规划，尚未开发。当前「代理配置」页面保留「代理配置功能暂未开放」占位说明。需要区分：Stage 4A/6 曾交付的代理、订阅与 Mihomo 具体功能已在 PR #9 中移除，那是历史实现的移除；代理配置功能本身尚未实施，不属于已取消功能。具体开发内容与范围在启动该阶段时由项目负责人确定，本路线图不预先扩展其范围。

### Stage 10——多开同步

基于 CDP 的主控—被控同步：每个实例启动时分配仅监听 127.0.0.1 的独立调试端口（仅存内存）。主实例的网页输入由注入页面隔离执行环境的观察脚本经 CDP Runtime Binding 回传（鼠标、滚轮、键盘、文本增量与页面可见性），跟随实例在各自独立的 CDP 连接与有界队列上执行；标签对应关系只由 CDP 的 Target 标识与创建结果显式建立，活动标签由 Page Visibility API 确定，不使用标题、URL 或列表顺序猜测。不使用 SendInput、全局键鼠钩子、UI Automation 或窗口激活；浏览器自身界面（地址栏未提交输入、菜单、扩展弹窗等）不在同步范围内。窗口排列与恢复使用原生窗口接口且不激活跟随窗口。实现完成，待 Windows 11 实机验收。

### Stage 11——程序内更新与发布

仅在代码签名 / 可信发布签名方案就绪后，才提供经 GitHub Releases 的程序内更新（在此之前从 GitHub Releases 手动下载）；更新须验证下载内容、保留全部便携数据，并在失败时回滚。尚未开始。

### Stage 12——完整备份与恢复（最终阶段）

备份与恢复固定为最后一个功能阶段：它必须以最终形态覆盖完整的用户数据体系，因此从盘点成品应用所持久化的全部内容开始。要点：

- 用户创建的 `.dbak` 备份包（清单 + 逐文件 SHA-256），格式带独立版本号。
- 独立备份口令（PBKDF2-HMAC-SHA256 + AES-256-GCM），使备份能跨机器、跨 Windows 用户恢复；DPAPI 本身不是跨机器机制。
- 恢复先在暂存区校验完整备份，之后才替换当前数据；恢复失败时当前数据不受影响。
- 数据层内部的迁移前快照（见 [DATABASE.md](DATABASE.md)）是底层安全设施，不属于本功能。

## 已取消的功能

- **独立 Chromium 下载、安装与管理**：已取消（PR #11）。浏览器只能由用户手动登记本机已有程序；`kernels` 表作为历史结构保留。
- **首次启动欢迎页 / 数据导入选择**：已取消。应用直接启动并初始化便携数据目录。
